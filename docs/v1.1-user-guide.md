# Pure 2D Auto-Label V1.1 User Guide

Status: local deployment candidate; every prediction still requires review

## What Changed From V1

- Fine-tunes the selected RTMDet-Tiny checkpoint on every reviewed daytime
  camera view for deployment, including the previously missing
  `s00/back_left` excavator view.
- Preserves the complete 16:9 image during fine-tuning. Mosaic, MixUp, random
  crops, and flips are disabled so large edge-touching machines are not cut.
- Applies cross-class NMS at IoU 0.5. When `Truck`, `WaterTruck`, and `Car`
  produce near-identical boxes for one machine, only the strongest label is
  exported.
- Writes score/NMS settings and model/config/checkpoint/dataset hashes into the
  auditable prediction output and run summary.
- Produces total boxes, per-class counts, empty images, duplicate IDs, failures,
  and throughput automatically after every batch run.

## Run

From the repository root:

```powershell
.\run_v1_1_autolabel.bat "C:\path\to\car5_20260611_day_02"
```

PowerShell exposes the review threshold and cross-class NMS threshold:

```powershell
.\run_v1_1_autolabel.ps1 `
  -DatasetRoot "C:\path\to\car5_20260611_day_02" `
  -Output ".\artifacts\v1_1_predictions\predictions.jsonl" `
  -ScoreThreshold 0.2 `
  -CrossClassNmsIou 0.5 `
  -WaterTruckMinScore 0.6 `
  -WaterTruckAmbiguityMargin 0.15 `
  -BatchSize 32
```

The launcher automatically chooses the newest `best_coco_bbox_mAP_epoch_*.pth`
from the V1.1 deployment-training directory. Pass `-Checkpoint` to pin a
specific reviewed weight.

## Threshold Modes

- `0.2`: default review-candidate mode; higher recall and more deletion work.
- `0.4`: conservative mode; fewer false boxes but substantially more manual
  drawing for missed objects.

The default remains a human-in-the-loop proposal mode. No score is an
authorization to accept safety-critical mine labels without review.

## Mining Vehicle Label Policy

`Truck` is the safe default for an ambiguous heavy vehicle. V1.1 only exports
`WaterTruck` when its score is at least 0.6. A lower WaterTruck prediction is
kept as a box but relabeled to Truck, with `raw_label` and
`postprocess_reason` retained for audit. If overlapping Truck and WaterTruck
boxes compete, WaterTruck must exceed the alternative by at least 0.15.

On the 84 reviewed WaterTruck instances available for calibration, raising the
WaterTruck threshold from 0.2 to 0.6 changed precision from 46.6% to 98.6% and
recall from 97.6% to 86.9%. These are in-domain calibration figures, not an
independent mine-site test.

## Evaluation Boundary

Two checkpoints have deliberately different purposes:

- The original fold-0 V1 checkpoint never sees `s00` and is used for honest
  generalization measurement.
- The V1.1 deployment checkpoint sees all available reviewed views and is used
  for production inference. Its all-data metric is a fit/regression check, not
  an independent test score.

Never describe an all-data V1.1 score as validation accuracy. A genuinely new
mine sequence is still required for the final industrial acceptance test.

The complete measured results, including the failed honest fold-0 experiment,
are recorded in `docs/v1.1-evaluation.md`.

## Rollback

V1 remains at Git commit `780faaf`. V1 and V1.1 use separate launchers,
training directories, checkpoints, and output directories. Rolling back means
running `run_v1_autolabel.*` or checking out the V1 commit; no V1 weight or
prediction file is overwritten.
